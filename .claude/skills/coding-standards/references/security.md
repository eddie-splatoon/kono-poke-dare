# セキュアコード

このゲームは、サーバー、ログイン、DB を持たない静的サイトである(#1 のセクション 2)。リポジトリも配信データも公開されているので、読まれても安全であるように書く。

Next.js の書き方は、導入済みの `node_modules/next/dist/docs/01-app/02-guides/static-exports.md` も確認する(このリポジトリの Next.js は学習データと異なることがある)。

## 正解データの扱い

- 正解データは配信データに含まれるものとして扱う。見えにくくする工夫はしても、守れるとは考えない
- 見えにくくする処理を、セキュリティ対策として扱わない
- 通常の画面に、未公開のヒントや回答前の正解を表示しない
- 配信データから正解を読めることは、脆弱性として扱わない

## 外部への送信

- 外部へデータを送信しない。スコア、履歴、回答はブラウザの外に出さない
- 解析ツール、広告、外部の API など、外部と通信するものを追加しない。必要なときは、先に Issue で相談する

## 端末内のデータ

- スコアと履歴は IndexedDB に保存する
- 「1 日 1 回」は IndexedDB の日付キーで管理する。データを消せば回避できることは許容する
- IndexedDB の値は利用者が書き換えられるので、読み込むときに型と範囲を検証する。不正な値でゲームが壊れないようにする

## 入力

- 回答の入力、URL のクエリ、IndexedDB の値をすべて信頼しない
- `dangerouslySetInnerHTML` は原則として使わない。使うときは理由を PR に書く

## 秘密情報

- ビルド成果物はすべて公開される。ゲームのコードと配信データに秘密情報を入れない
- 秘密情報に `NEXT_PUBLIC_` を付けない
- トークンやパスワードをコミットしない。`.env*` をコミットしない
- 秘密情報や個人情報をログに残さない

## 依存

新しい依存を追加するときは、必要性と提供元を確認する。

## CI

- アクションはコミット SHA で固定する
- `permissions` を最小にする
- `pull_request_target` を使わない
- PR の本文やタイトルは `${{ }}` で `run` に直接埋め込まず、環境変数で渡す(`.github/workflows/identity.yml` の方式)
- `actions/checkout` には `persist-credentials: false` を付ける

## 権利

公式の画像、ロゴ、音声を追加しない。権利に関わる判断は、`legal` ラベルの Issue で行う。

## 脆弱性の報告

脆弱性は、公開の Issue や PR に詳細を書かない。[`SECURITY.md`](../../../../SECURITY.md) の窓口を使う。

## レビュー

PR の前に `/security-review` を実行し、指摘に対応する。
