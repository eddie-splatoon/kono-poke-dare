# 問題データの形式と検証

## 概要

問題データをゲームロジックから分離して、静的ファイルとして配信する。データの形式、ヒントの書き方、配信方法を定め、機械的に確かめられる項目を CI で検証する。

## ドメインルール

### 姿違い

- 種族で 1 問とする。姿ごとに問題を分けない
- 姿違いには終盤のヒント(8〜10)で触れる
- 姿の名前は `aliases` に入れて正解にする。種族として合っている回答を不正解にしないためである
- `aliases` の表記は、`メガ`、`キョダイマックス`、`アローラ`、`ガラル`、`ヒスイ`、`パルデア` を種族名の前に付けた形にそろえる。衣装や一時的な姿(ピカチュウのキャップ、ぬしポケモンなど)は入れない

### ヒントの難易度の順序

1 が最も難しく、10 が最も易しい。順序は機械的に確かめられないので、抽出して読んで確認する。

| ヒント | 内容                                                               |
| ------ | ------------------------------------------------------------------ |
| 1〜2   | 多くの種族に当てはまる周辺的な特徴(能力の傾向、覚える技の傾向など) |
| 3〜4   | 大きさ、重さ、生息する環境など、候補を絞る事実                     |
| 5〜6   | 登場した世代、性格や生態、見た目の一部                             |
| 7〜8   | タイプ、進化の関係                                                 |
| 9〜10  | 姿違い、代表的な外見、名前の文字数や頭文字など、ほぼ特定できる情報 |

### 書き方の基準

- 独自の文章で書く。図鑑の説明文を転載しない
- 公式の画像、ロゴ、音声を使わない
- 確かめられる事実だけを書く。タイプや進化などは、信頼できるデータと照合する
- 正解の名前と別名を含めない
- 1 文で書き、文末を「である」調にそろえる

### 重複と混入の判定

- ヒントの重複は、同じ問題の中だけで判定する。タイプなどの事実は、別の問題と同じ文になることがある
- 比較には回答と同じ正規化(`normalizeAnswer`、`docs/specs/game-rules.md`)を使う
- 名前の混入は部分一致で判定する。短い名前が別の語の一部として一致したときは、文を書き換えて解消する

### 配信方法

全データを 1 度に配信しないように、1 問を 1 ファイルにする。遊ぶ日の 1 問と問題数だけを取得すれば済む。`public/` は静的書き出しにそのまま含まれるので、ビルド処理を増やさない。

問題番号は 1〜問題数の連番とする(`questionNumberForDay` が返す範囲)。

### 全種類の確認

`scripts/check-question-data.test.ts` の `EXPECTED_QUESTION_COUNT` を期待する問題数とする。図鑑の順に世代ごとに増やし(151、251、386、493、649、721、809、905)、全種類のデータの完成時(#16)に 1025 にする。

### データの作成

事実のヒントはデータから生成し、外見と特徴のヒントは手書きする(#16)。

| ヒント | 内容                               | 作り方 |
| ------ | ---------------------------------- | ------ |
| 1、2   | 最も高い基礎能力、基礎能力の合計   | 生成   |
| 3、4   | 高さ、重さ                         | 生成   |
| 5      | 初登場の世代                       | 生成   |
| 6      | 外見の一部                         | 手書き |
| 7、8   | タイプ、進化の関係                 | 生成   |
| 9      | 姿違い、または代表的な特徴         | 手書き |
| 10     | 名前の文字数と頭文字               | 生成   |

```text
PokeAPI → .cache/pokeapi/(コミットしない) → data/question-sources/facts/gen-N.json
                                                      ↓
              data/question-sources/hand-written/gen-N.json → public/data/questions/NNNN.json
```

- 生成した文が名前を含んで検証を通らないときは、手書きデータの `overrides` で該当のヒントだけ書き換える
- 取得(`pnpm data:fetch <世代>`)は手元で手動で実行する。CI とゲームは PokeAPI と通信しない
- 取得は順番に間隔を空けて行い、応答をキャッシュする(PokeAPI の Fair Use Policy)

### 事実の照合

生成するヒントは PokeAPI のデータから機械的に作るので、取得元と取得日と件数を PR に記録する。手書きのヒントは機械的に照合できないので、全件を読んで確認し、その結果を PR に記録する。

## 入出力

### ファイル

| パス                                | 内容                     |
| ----------------------------------- | ------------------------ |
| `public/data/questions/index.json`  | `{ "count": 問題数 }`    |
| `public/data/questions/NNNN.json`   | 1 問のデータ(`0001.json`) |

問題のファイルの項目は次のとおりである(`Question`)。

| 項目      | 型         | 範囲                                     |
| --------- | ---------- | ---------------------------------------- |
| `number`  | `number`   | 1〜問題数の整数。ファイル名の番号と同じ  |
| `name`    | `string`   | 正解として表示する名前                   |
| `aliases` | `string[]` | `name` のほかに正解とする名前。空でもよい |
| `hints`   | `string[]` | 難しい順のヒント 10 個                   |

架空の例を示す。

```json
{
  "number": 1,
  "name": "カセツモン",
  "aliases": ["メガカセツモン"],
  "hints": ["ヒント 1 の本文", "…", "ヒント 10 の本文"]
}
```

### 関数

| 関数                                        | 入力                         | 出力                        |
| ------------------------------------------- | ---------------------------- | --------------------------- |
| `validateQuestion`                          | `unknown`                    | 問題点の `string[]`         |
| `validateQuestionManifest`                  | `unknown`                    | 問題点の `string[]`         |
| `validateQuestionSet`                       | 問題番号の配列、期待する問題数 | 問題点の `string[]`         |
| `createStaticQuestionRepository`            | `baseUrl`、`fetch`           | `QuestionRepository`        |
| `checkQuestionData`(テストから使う)         | ディレクトリ、期待する問題数 | 問題点の `string[]`         |

`baseUrl` は `basePath` を含み、末尾に `/` を付けない(例: `/kono-poke-dare/data/questions`)。

`data/question-sources/` の項目は次のとおりである。

| ファイル                | 項目                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| `facts/gen-N.json`      | `SpeciesFacts` の配列(番号、名前、世代、高さ、重さ、タイプ、基礎能力、進化、`varieties`)                |
| `hand-written/gen-N.json` | 番号をキーとする `HandWritten`(`appearance`、`signature`、`aliases`、省略できる `overrides`)           |

## エラー

| エラー                     | 条件                                                                  |
| -------------------------- | --------------------------------------------------------------------- |
| `InvalidQuestionDataError` | 応答が JSON として読めない、検証を通らない、ファイルの番号と一致しない |
| `QuestionDataFetchError`   | 問題のファイルの 404 以外の HTTP エラー、`index.json` の HTTP エラー  |

通信そのものの失敗は、`fetch` の例外をそのまま伝える。いずれの場合も、ゲームの状態を進めない。

## セキュリティ

- 配信データの応答を信頼しない。内側へ渡す前に検証する
- `questionNumber` は端末内のデータから来ることがあるので信頼しない。1〜問題数の整数だけをファイル名にする
- 同じオリジンの静的ファイルを取得するだけで、外部へデータを送信しない
- 配信データから正解を読めることは許容する(`security.md`)
- PokeAPI との通信は手元の取得スクリプトだけで行い、利用者のデータを送らない。応答に含まれる URL を辿るので、取得先のオリジンを PokeAPI に限る
