# ヒントの評価シート

## 概要

手書きのヒントと難易度の順序を、人が観点ごとに点数で評価するための HTML を生成する。採点の結果を CSV で書き出し、ヒントの修正の入力にする。ゲームには含めず、手元で `file://` で開いて使う。

## 要件

## ドメインルール

### 観点

各観点を 1〜5 で採点する。すべて高いほど良い。判断できないときは `NA` にして、点数を強制しない。

| 列名               | 観点                                                     | 5                      | 3                                                | 1                                        |
| ------------------ | -------------------------------------------------------- | ---------------------- | ------------------------------------------------ | ---------------------------------------- |
| `accuracy`         | 手書きの正確さ(ヒント 8、9。資料と照合していなければ NA) | 資料と照合して誤りなし | 細部に疑いがある                                 | 明確な誤り(色、形、モチーフ)             |
| `hint8_strength`   | 外見の手がかり(ヒント 6〜8 で思い浮かぶ候補の数)         | 1〜3 匹                | 4〜10 匹                                         | 11 匹以上                                |
| `hint9_strength`   | ヒント 9 の手がかり(ヒント 6〜9 で思い浮かぶ候補の数)    | 1〜2 匹                | 3〜5 匹                                          | 6 匹以上                                 |
| `difficulty_order` | 難易度の順序(6 → 10)                                     | 順に易しくなる         | 入れ替わりがあるが許容できる(組をコメントに書く) | 明らかに逆転している(組をコメントに書く) |
| `wording`          | 文面の自然さ(全ヒント)                                   | 自然である             | 少し不自然である                                 | 意味が通らない、直すべき                 |
| `redundancy`       | ヒント 9 の新しさ(ヒント 1〜8 との重なり)                | 新しい情報だけである   | 一部が重なるが、新しい情報もある                 | 新しい情報がない                         |

いずれかの評点が 2 以下の種族を「要修正」とする。3 以下の評点には、どのヒントのどこが問題かをコメントに書く。

候補の数は、高さや重さなどの数値で図鑑を検索せず、ポケモンに詳しい人が記憶で思い浮かべる数で数える。数値まで使うと、ほぼすべての種族が 1 匹に決まってしまい、差が付かないためである。

観点は、2 回の試し採点を受けて見直した。文の型で評点が決まらないように候補の数を基準にし、`accuracy` は照合の有無を区別する。名前の漏れは人の判定がばらついたので採点せず、機械的に一覧にする(R-47)。一覧の 171 件のうち 133 件はヒント 9 で、多くは進化前の名前によるものである。すべてが問題ではないので、1 件ずつ判断する。ヒント 10 は文字数と頭文字を示すので、対象にしない。

外見は [公式ポケモンずかん](https://zukan.pokemon.co.jp/) の画像などと照合する。図鑑の文章をコメントやヒントに転載しない。シートには外部の URL を載せない。

### 優先の種族

各 PR と #34 に、確信を持てなかった表現として書かれた種族を `scripts/hint-review/priority-notes.ts` に記録し、カードに疑いの内容を表示する。

### 採点の流れ

1. `pnpm data:review` で `.review/hint-review.html` を生成し、ブラウザで開く
2. 採点する。採点は `localStorage` に自動で保存する
3. CSV を書き出して、修正の入力にする
4. ヒントを直したら再生成する。ヒントが変わった種族だけが未採点に戻る

`.review/` は `.gitignore` の対象なので、worktree を削除すると一緒に消える。`localStorage` はファイルの場所やブラウザによって引き継がれないことがあるので、別の場所で続けるときは CSV を取り込む。

観点や基準を変えたら、別の基準で付けた評点を引き継がない。`localStorage` の保存キーの番号を上げる。列が足りない古い CSV は取り込めない(R-12)。

## 入出力

### コマンド

| コマンド           | 出力                                                     |
| ------------------ | -------------------------------------------------------- |
| `pnpm data:review` | `.review/hint-review.html`、`.review/name-fragments.csv` |

### CSV

UTF-8(BOM あり)、RFC 4180 形式で、列は次の順に並ぶ。

| 列                                                                    | 内容                                         |
| --------------------------------------------------------------------- | -------------------------------------------- |
| `number`、`name`、`generation`                                        | 図鑑番号、名前、世代                         |
| `priority`                                                            | 優先の種族なら `1`、それ以外は `0`           |
| `hints_version`                                                       | 全ヒントのハッシュ                           |
| `accuracy`、`hint8_strength`、`hint9_strength`、`difficulty_order`、`wording`、`redundancy` | `1`〜`5`、`NA`、または空(未採点)             |
| `total`、`min_score`                                                  | 数値の評点の合計と最小値。なければ空         |
| `needs_fix`                                                           | 2 以下の評点があれば `1`、それ以外は `0`     |
| `comment`                                                             | コメント                                     |
| `hint_8`、`hint_9`                                                    | 採点したときのヒントの文(修正の参考)         |

`hints_version` は `v` で始める。表計算ソフトで保存し直したときに、数値として扱われて値が変わらないようにするためである。

取り込みで読むのは `number`、`hints_version`、全観点、`comment` だけで、ほかの列は無視する。

### キーボード

| キー       | 動作                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| `1`〜`5`   | 選択中のカードの、次の未採点の観点に評点を付ける                         |
| `0`        | 同じく `NA` にする                                                       |
| `c`        | 選択中のカードのコメント欄へ移る                                         |
| `Esc`      | コメント欄から抜ける。全観点が揃っていれば次のカードへ移る               |

## エラー

| 条件                                 | 振る舞い                                 |
| ------------------------------------ | ---------------------------------------- |
| 取り込む CSV の形式が不正である      | 採点を変更せず、メッセージを表示する     |
| 取り込む CSV の行が不正である        | その行だけを採用せず、件数を表示する     |
| 保存値が読めない                     | 採点なしで始める                         |
| `localStorage` に保存できない        | メッセージを表示し、CSV の書き出しを促す |
| 優先の種族の名前がデータにない       | 生成をエラーにする                       |

## セキュリティ

- CSP で通信を禁止し、外部へデータを送信しない。評点とコメントは端末内の `localStorage` と、利用者が書き出す CSV にだけ残る
- 取り込む CSV と `localStorage` の値を信頼せず、番号、評点、`hints_version` を検証する
- 画面へは `textContent` で出力し、`innerHTML` を使わない
- 数式として解釈されるセルに `'` を前置し、CSV インジェクションを防ぐ。取り込むときに元へ戻す
- 問題データは `<` をエスケープして埋め込む
- 生成物は `src/` と `public/` の外に置くので、配信されない
